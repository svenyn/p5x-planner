Keep or feed

Every card is scored against every character you own, and rated by its best match. With a large inventory this is the fastest way to find what is safe to feed away.

Confidence flags. high means a full published build exists. med means sources conflicted or were vague. low means no build has been published and the targets are archetype defaults I generated — treat those as a starting point, not gospel. Every target is editable.

Where this data came from, and what to distrust

Everything here was assembled from community guides in August 2026, not from the game client. Four things are worth knowing before you trust a recommendation:

  1. Guide sites use different set names. Game8 and Prydwen translate the same sets differently, and Fragster uses a third scheme. Confirmed equivalences are handled on import (Strength is Power, Abundance is Prosperity, and so on), but two names — Ruin and Prudence — could not be matched to anything, so they are listed as separate sets with unknown 2-piece effects.
  2. Main stat magnitudes are not published anywhere. No source lists what a main stat is actually worth at level 25, so the optimiser weights main stats by priority rather than by real numbers.
  3. Substat roll values come from a single source and were never checked against the client. If a number looks wrong, it may be.
  4. Twenty-five characters have no published build. They carry archetype defaults I generated and are flagged low on the Roster tab.

All of it is editable, and all of it gets much better the moment it is checked against real screenshots from your own game.

Danger zone

Scanning your cards in

Typing four thousand cards into the Inventory tab is not a plan. The ocr/ folder in this repository reads card detail panels out of screenshots or a screen recording and writes the JSON file the Save / Load tab imports. Six steps, and only two of them are per-scan — the install and the calibration are done once.

It reads pixels, nothing else. The pipeline never sends input into the game client, never reads its memory and never talks to a server. You capture the screenshots yourself, by hand, and it works on the image files afterwards. Input automation is a ban risk on an account worth thousands of cards, so it is deliberately not on the table.

Install the tooling once

You need Python 3.10+, Tesseract OCR on your PATH, and — only if you are scanning a video rather than screenshots — ffmpeg, also on your PATH. Then, from the repository root: 

pip install -r ocr/requirements.txt
npm run export-tables

That second command writes dist/tables.json: every slot, set, substat, alias and character name exported straight out of src/data.js. The pipeline matches OCR text against that file rather than against a hand-copied list, so it cannot drift from the app it is feeding. Re-run it after any edit to src/data.js.

Capture the cards per scan

Open a card's detail panel in-game and capture it. Two routes, both landing in the same place:

Screenshots One screenshot per card, all in one folder. Filenames do not matter; .png, .jpg and .jpeg are all read.
Screen recording Record while you step through cards, leaving each panel on screen for about a second. The pipeline samples two frames a second and then drops any frame whose perceptual hash is close to the last one it kept, so a long recording collapses to roughly one frame per card instead of one per frame.

Four capture rules decide whether this works at all:

  1. One rarity per run. Rarity is not printed on the detail panel anywhere, so you supply it on the command line and every card in the run is stamped with it. Scan your 5★ separately from your 4★.
  2. One slot tab per run, too. The slot is read off the Space/Sun/Moon/Star/Sky tab strip by colour — which tab is highlighted red — because the game's title font is unreadable to OCR. Passing the slot on the command line as well gives it a fallback for frames where the strip is hidden, and if the two disagree the card goes to review instead of being filed wrongly.
  3. Same resolution and window size throughout. Crop boxes are stored as fractions of the frame, so they survive between sessions — but not across a resolution change without recalibrating.
  4. Nothing on top of the panel. A tooltip, popup or notification over a field reads as noise and sends that card to review.

Two things are never scanned because the panel does not show them: rarity, handled above, and which character the card is equipped on. You set that here instead — run the tab and press Mark these as equipped.

Calibrate the crop regions once per device

The pipeline has to be shown where each field sits on your screen. Point it at a single real screenshot: 

python ocr/calibrate.py path/to/one-screenshot.png

A window opens on that image, once per field. Drag a box around the field and press Enter or Space to confirm; press Enter without dragging to skip a field this particular card does not have, such as the fourth substat on a three-substat card; Esc quits without writing anything. What to aim at:

FieldAim at
slot_tabsThe whole Space/Sun/Moon/Star/Sky tab strip, top-left. Read by colour, not text, so the box only has to contain all five tabs.
titleThe bracketed set name inside the Set Effect box, lower right — e.g. [Futility]. Not the big stylized title at the top: that jagged comic-book font could not be read under any Tesseract configuration tried against a real screenshot. The same name appears in the Set Effect box in a plain readable font, which is why it is read from there.
levelThe Lv.25 text, tight around it.
main_labelThe name of the first stat — the one with its own icon, e.g. Crit Rate — not its number. Sun and Space cards have a fixed main stat, so this is not used for them.
sub1…sub4A label box and a value box for each substat row. The value box matters more than it looks: ATK, DEF and HP each exist as both a flat and a percentage substat under the same label, and only the % in the value tells them apart.

The result lands in ocr/config/crop_regions.json as fractions of the image, so it is resolution-independent and only has to be done once per device. To redo a single bad box without dragging all twelve again: 

python ocr/calibrate.py path/to/one-screenshot.png --only sub4_label sub4_value

Run the pipeline per scan

# a folder of screenshots
python ocr/pipeline.py path/to/screenshots --rarity 5 --slot Star --out cards.json

# or a screen recording — same command, ffmpeg does the rest
python ocr/pipeline.py path/to/recording.mp4 --rarity 5 --slot Star --out cards.json

Every card that comes out is checked against the same rules this app applies to a pasted line or a loaded save file — legal slot, legal set for that slot, legal main stat, substat count for the rarity, no substat duplicating the main, no value beyond what five maximum rolls could produce. Two files are written:

cards.jsonCards that read cleanly and passed validation. This is the file you import.
cards-review.jsonEverything else — each entry carrying the source frame's filename, the card exactly as it was read, a per-field confidence score, the validation errors and a plain-English note about what was ambiguous.

A card that fails on one field still shows you every other field it read, so working the review pile is usually a one-number fix rather than a rescan. Try five screenshots before you try five hundred.

Import into the planner per scan

Go to → Import cards (merge) and pick cards.json. This merges rather than replaces: new cards are added, cards that have leveled up since your last scan are updated in place, exact resubmissions are skipped, and anything that looks like a card you already own but whose numbers do not line up as a clean level-up is parked in a review table where you choose skip, add as new or replace. Rescanning a slot you have already scanned is therefore safe.

Then press Download save file on that same tab. This app deliberately keeps nothing between sessions — no cookies, no browser storage — so an import you do not save is an import you lose when the tab closes.

Work the review pile per scan

Open cards-review.json. Each entry names the frame it came from and what went wrong. Three ways out, cheapest first:

  • The card is right apart from one number — fix it by hand on the tab, either in the single-card form or as a bulk-paste line.
  • The same error appears across many cards — a crop box is wrong, not the cards. Recalibrate that one field with --only and re-run the batch.
  • The frame itself is bad — caught mid-scroll, occluded, or not a detail panel at all. Delete it and recapture that card.

When it goes wrong

What you seeWhat it usually means, and what to do
Every card lands in review with could not resolve set from title The title box is on the big stylized card title, which OCR cannot read. Recalibrate it onto the bracketed name in the Set Effect box: --only title.
Levels come back as nonsense — Lv 128 on a 5★ The level box is catching neighbouring text or the enhancement bar. Tighten it with --only level. The validator catches this one for you, since 25 is the ceiling.
could not read the slot tab strip The strip is occluded or out of frame, or the frame is not a detail panel at all. Pass --slot so there is a fallback, and drop the frames that are not cards.
slot tab strip reads "Sky" but slot="Star" was passed in The capture mixed two slot tabs. What the strip says wins, because per-frame evidence beats a batch-wide assumption, but the card still goes to review rather than being silently resolved. Split the capture by tab.
"Ruin" is not a legal set for Sky Not your fault and not fixable by recalibrating. Two set names from the community guides — Ruin and Prudence — could not be matched to any verified set list. See the provenance notes on the tab.
A substat value is rejected as out of range That sub{n}_value box is overlapping the row above or below. Recalibrate the one box.
A video yields far more frames than you have cards The dedupe threshold is too tight for your capture. Raise --max-distance (default 4), or lower --fps (default 2).
A video yields fewer frames than you have cards Panels were held on screen too briefly and got deduped away. Raise --fps, lower --max-distance, or re-record more slowly.
A set or stat name resolves to the wrong thing OCR text is matched exactly first, then by alias, and only then fuzzily above an 80% threshold — a fuzzy hit is recorded with its confidence in the review file. If a name is wrong across the board, the fix belongs in src/data.js, followed by npm run export-tables.

If you would rather not install any of that

Nothing here is required. The tab takes cards one at a time through a keyboard-driven form, and its bulk-paste box takes one card per line in the format Slot | Set | Rarity | Level | Main stat | sub value, sub value, …. Stat and set names are matched loosely there too, so CDMG, Crit DMG and Crit Multiplier all land on the same stat. For a few dozen cards that is faster than calibrating anything. It is the four-thousand-card case the pipeline exists for.
